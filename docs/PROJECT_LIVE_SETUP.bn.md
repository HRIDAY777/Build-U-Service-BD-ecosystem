# প্রজেক্ট অ্যাকাউন্ট লাইভ চালুর সেটআপ তালিকা

আপনার উত্তর: পেমেন্ট, পেআউট ও ডিজিটাল স্বাক্ষরের অনুমোদিত অ্যাকাউন্ট এখনও নেই। তাই বর্তমানে আবেদন, পর্যালোচনা, ব্যক্তিগত চুক্তি PDF, নাম লিখে সম্মতির প্রমাণ এবং ম্যানুয়াল হিসাব ব্যবহার করা যাবে। স্বয়ংক্রিয় অর্থ গ্রহণ/পাঠানো চালু নেই।

## ১. ব্যবসা ও চুক্তির প্রস্তুতি — আপনার দায়িত্ব

- কোম্পানির পরিচয়, দায়িত্বপ্রাপ্ত ব্যক্তি, ব্যবসার ব্যাংক অ্যাকাউন্ট ও যোগাযোগের তথ্য প্রস্তুত করুন। প্রয়োজনীয় কাগজপত্রের চূড়ান্ত তালিকা সংশ্লিষ্ট প্রতিষ্ঠান থেকে নিন।
- গ্রাহকের কাজের মূল্য, হস্তান্তর, কিস্তি, বাতিল ও ফেরতের শর্তসহ চূড়ান্ত চুক্তি প্রস্তুত করুন। বিনিয়োগের চুক্তি ও অর্থ সংগ্রহের অনুমোদন আলাদাভাবে যাচাই করান। ওয়েবসাইটের প্রস্তাবিত হিসাব অনুমোদনের বিকল্প নয়।
- পর্যালোচিত PDF অ্যাডমিন আপলোড করবেন। গ্রাহক লগইন করে PDF ডাউনলোড ও নিজের নাম লিখে সম্মতি দেবেন। এটি প্রত্যয়িত ডিজিটাল স্বাক্ষর নয়।

## ২. পেমেন্ট গ্রহণ — প্রতিষ্ঠান + পরবর্তী উন্নয়ন

- অনুমোদিত পেমেন্ট প্রতিষ্ঠানের মার্চেন্ট অ্যাকাউন্ট খুলুন এবং গ্রাহকের বিল ও বিনিয়োগের অর্থ—কোন লেনদেন অনুমোদিত তা লিখিতভাবে নিশ্চিত করুন।
- SSLCOMMERZ বেছে নিলে Store ID, Store Password, sandbox ও live অ্যাক্সেস এবং settlement ব্যাংক সেটআপ প্রতিষ্ঠান থেকে নিতে হবে। গোপন তথ্য চ্যাটে দেবেন না; সার্ভারের নিরাপদ পরিবেশে বসাতে হবে।
- বর্তমান SSLCOMMERZ সংযোগ সাধারণ অর্ডারের জন্য। প্রজেক্ট আবেদন/কিস্তির সঙ্গে নতুন সংযোগ, সঠিক পরিমাণ যাচাই, IPN, duplicate callback প্রতিরোধ, ব্যর্থ/বাতিল/ফেরত ও হিসাব মিলানোর পরীক্ষা বাকি। শুধু key বসালে প্রজেক্ট পেমেন্ট চালু হবে না।

## ৩. পেআউট — প্রতিষ্ঠান + পরবর্তী উন্নয়ন

- ব্যবসার ব্যাংক বা অনুমোদিত payout প্রতিষ্ঠানের সঙ্গে disbursement সুবিধা ও চুক্তি নিন। API আছে কি না, সীমা, চার্জ, beneficiary যাচাই ও settlement সময় জানুন।
- API থাকলে sandbox, অনুমোদন নিয়ন্ত্রণ, এক লেনদেন একবার পাঠানো, callback যাচাই, ব্যর্থ লেনদেন ও reconciliation সংযোগ তৈরি করতে হবে।
- API না থাকলে ব্যাংকের মাধ্যমে অর্থ পাঠিয়ে প্রকৃত রেফারেন্স ম্যানুয়াল ledger-এ লিখুন। Ledger-এ লেখা অর্থ পাঠানোর কাজ করে না।

## ৪. প্রত্যয়িত ডিজিটাল স্বাক্ষর — ঐচ্ছিক প্রতিষ্ঠান + সংযোগ

- আপনার চুক্তির জন্য উপযুক্ত সেবা বেছে নিন এবং গ্রহণযোগ্য স্বাক্ষর পদ্ধতি নিশ্চিত করুন। উদাহরণ হিসেবে DocuSign ব্যবহার করলে developer account, integration key, authentication ও production go-live প্রস্তুতি প্রয়োজন। এটি নির্বাচিত বা সংযুক্ত হয়নি।
- signer পরিচয়, document version, signed PDF, provider certificate ও callback যাচাইয়ের সংযোগ তৈরি ও পরীক্ষা করতে হবে। বর্তমান typed-name evidence দিয়ে এই কাজ সম্পন্ন হয়েছে বলা যাবে না।

## ৫. সার্ভার ও পরিচালনা

- ডোমেইন, HTTPS, production database, email, backup ও restore পরীক্ষা প্রস্তুত করুন।
- চুক্তির ফাইল private রাখুন; public media URL-এ প্রকাশ করবেন না। production-এ আপলোড scan, সংরক্ষণ/মুছে ফেলার নীতি ও backup access নির্ধারণ করুন। বর্তমানে PDF header/size যাচাই হয়; malware scan হয় না।
- Operations আবেদন পর্যালোচনা করবেন, Finance প্রকৃত লেনদেন লিখবেন, Content প্রকল্পের আপডেট দেবেন। সাধারণ গ্রাহক অন্যের আবেদন/চুক্তি দেখতে পারবেন না।
- আগে sandbox-এ সফল/ব্যর্থ/duplicate/refund/payout/signature ও অনুমতি পরীক্ষা; তারপর সীমিত live লেনদেন এবং ব্যাংকের হিসাবের সঙ্গে মিলিয়ে চালু করুন।

## পরে যে তথ্য দেবেন

বর্তমান প্রস্তুতি যাচাই করতে backend থেকে `python manage.py check_project_launch` চালানো যায়। এটি কোনো পেমেন্ট পাঠায় না এবং key/password প্রকাশ করে না। কোন settings অনুপস্থিত, migration বাকি কি না এবং কোন সংযোগ এখনও তৈরি হয়নি তা দেখায়। সব settings থাকলেও প্রতিষ্ঠান ও live পরীক্ষা ছাড়া নিজে থেকে প্রস্তুত ঘোষণা করে না।

প্রতিষ্ঠানের নাম, অ্যাকাউন্ট অনুমোদনের অবস্থা, অনুমোদিত লেনদেনের ধরন, sandbox আছে কি না এবং সংযোগের official documentation link। API key, password বা ব্যাংকের গোপন তথ্য এখানে দেবেন না।
