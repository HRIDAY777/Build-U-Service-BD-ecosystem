# Private partner onboarding

Applicants sign in at `/partner-application`, submit a business division/name/contact/address, and upload up to ten private PDFs (5 MB each). No bank details or national ID are requested. Applicants can edit, withdraw a document, or cancel only while submitted or changes are requested. Editing resubmits the application; upload alone does not resubmit requested changes.

Reviewers need both `catalog.view_partnerapplication` and `catalog.change_partnerapplication`. A staff flag alone does not provide access. Superusers already have these permissions. Grant both only to authorized business reviewers; ordinary organization edit permission is insufficient. Django admin displays these records read-only. Decisions are made through the application page/API.

Review flow: submitted → reviewing → approved / rejected / needs_changes. Reviewers cannot review their own applications or documents. While reviewing, inspect each active document and record accepted/rejected with a required note. Decisions have a timestamp and an audit record linking reviewer, decision, note and file hash; raw reviewer identity is not exposed in applicant API output. Acceptance of an expired document is blocked. Approval requires at least one active document, every active document individually accepted, no expired active documents, an application note and verification reference. Approval creates a new approved organization owned by the applicant; it cannot claim or alter an existing organization, grant staff privileges, or execute payments. Approved/rejected/cancelled applications and document decisions are frozen. Business approval is not specialist licensing, pharmacy clearance, or proof of regulatory compliance.

Endpoints under `/api/v1/partner-applications/`: paginated own list/detail (authorized reviewers see all), create, PATCH, `capabilities/`, `cancel/`, `document/`, `documents/{id}/download/`, `documents/{id}/withdraw/`, and `review/`. Private downloads are attachment-only with no-store/nosniff headers. API output excludes storage URLs and owner identity. Mutations are audited; transitions lock the application in a database transaction. Approval cannot be replayed to create a second organization. Withdrawn files are retained for the audit trail and ignored for approval; they count toward the ten-document limit.

Document decisions use `POST documents/{id}/review/` with `status` (accepted/rejected) and required `note`. Withdrawn documents cannot be reviewed and do not count toward the approval gate. Corrections require the applicant to withdraw the rejected file, upload its replacement and resubmit. Every replacement starts pending. Migration `catalog.0012` sets existing document decisions to pending without changing previous application/organization approvals; it does not retroactively certify old files or revoke businesses.

Local file validation checks size and PDF header, not malware or document authenticity. Private production storage/scanning/retention policies, renewal monitoring and suspension after expiry, specialist reviewer eligibility, automatic notifications, searchable geography and duplicate-submission idempotency remain separate improvements. This milestone must not be presented as a complete regulated partner verification system.

Verification: backend tests cover private scope (including unauthorized staff), self-approval denial, document privacy, invalid files, expired-document replacement, guarded approval, preservation of existing businesses and terminal immutability. Browser coverage submits an actual test application/PDF, downloads privately, reloads and cancels; it does not certify uploaded content or legal review.
